# M1: Thin vertical slice (report)

Date: 2026-11-08 · Branch: `m1-vertical-slice` · Machine: Apple M2 Max, 32 GB, macOS 26.5.1 (development machine; not the reference laptop, see OD-2)

## Demonstration

The flow below is demonstrated end to end by the headless GUI test `crates/mf-desktop/tests/workflow.rs`. It drives the real app (egui_kittest + wgpu):

1. Open a damaged mesh. Import and analysis run on worker threads.
2. Diagnostics appear, and boundary loops are drawn in orange. Faces seen from behind (through holes) are tinted red.
3. Click **Apply** on `mesh.remove_small_components`. Its panel is generated from `specs/operations/mesh.remove_small_components.yaml`. The 20 islands (plus one hole sliver) are removed.
4. **Undo** restores them; **Redo** removes them again.

The same operation runs from the CLI with the same spec-derived arguments:

```bash
meshfixer gen-fixture damaged damaged-1m.stl --triangles 1000000
meshfixer inspect damaged-1m.stl --json
meshfixer remove-small-components damaged-1m.stl -o cleaned.stl --max-triangles 100
meshfixer render cleaned.stl -o cleaned.png
```

The desktop app also opened the 1M and 5M fixtures interactively (screenshots in `artifacts/m1/`).

## What we learned

1. **The 5M mesh crashed the viewport.** A single flat-shaded vertex buffer was 346 MB, over wgpu's 256 MB default limit. Buffers are now split into triangle-aligned chunks. This is the first concrete push towards M4's chunked geometry.
2. **Memory is the risk to watch.** 1.1 GB peak RSS for a 4.8M-triangle STL round trip includes file bytes and import scratch, but it's well above the 400 MB working-set budget (MF-GEO-002). The likely culprits are the STL weld (sorting 3 corners × 24 B per triangle) and the edge list for topology. M4 needs the counting-allocator measurement, and probably a streaming weld.
3. **STL hides some damage.** Exact-position welding on import merges unwelded seams, so they show up in OBJ and not in STL. That's correct behaviour, but tests for unwelded seams must use OBJ.
4. **Rendering into our own target was the right call.** It decoupled `mf-render` from egui's render pass (depth and MSAA), made the GUI testable headlessly, and let the view skip re-rendering when nothing changed (the status bar shows rendered-frame counts).
5. **egui's default font lacks ✔ ✘ ⟲ ⟳.** The UI now uses plain text.

## Deliberately temporary (evolves later)

- `Arc<Vec>` mesh storage → chunked copy-on-write in M2 (MF-DOC-002)
- Linear history stack → revision DAG with retained branches in M2 (MF-HIST-001)
- Whole-object operations only → targeted selections in M3 (MF-OP-003)
- Non-indexed flat-shaded GPU buffers rebuilt per revision → chunked incremental uploads in M4 (MF-RENDER-003)
